MEMORY DISCIPLINE · COMMITTED · REVIEWED · AUDITED

Save whatstays true

A short What this project is block stays loaded every turn, so the model knows what it is building, who it serves, and what the product refuses to compromise on.

A memory system can fill with notes that later sessions never read. Old snapshots can then steer new work in the wrong direction.

Harness Firmware saves only standing knowledge a person confirmed and the code cannot already explain. It commits that knowledge with the repo, audits whether local sessions read it again, and sends stale or unused entries into /refine for review.

Problem: one plausible assumption can corrupt every later step.

  1. Define done
  2. Gather evidence
  3. Attack the answer
  4. Verify the claim
  5. Report unknowns

VERIFICATION

Turn confident claims into checks, then challenge the result from fresh viewpoints.

V.01Verify ThisCompare a falsifiable claim under matched conditions

Problem: “it works” has no baseline or separating test.

  1. State the claim so it can fail
  2. Capture baseline
  3. Apply treatment
  4. Compare
  5. Return a verdict

Helps by: tying confidence to an observable difference.

Limit: missing or confounded evidence returns inconclusive.

READ THE SKILL →
V.02Impartial ReviewAsk fresh contexts to inspect the work

Problem: builder and reviewer can inherit the same assumptions.

  1. Freeze scope
  2. Start fresh reviewers
  3. Inspect the workspace
  4. Verify every finding
  5. Report contract fit

Helps by: widening coverage without treating reviewer confidence as proof.

Limit: fresh context does not automatically mean another model family.

READ THE SKILL →
V.03Codex ReviewHave Claude call a different model directly

Problem: a fresh reviewer can still share the builder’s model-family blind spots.

Helps by: avoiding pasted transcripts, copied diffs, and transcription loss.

Limit: cross-model review still needs verification and CLI availability.

  1. Claude selects the exact diff
  2. Claude runs Codex CLI review
  3. Codex reads the repo directly
  4. Codex writes a review file
  5. Claude verifies every finding
