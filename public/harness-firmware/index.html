WHAT MAKES IT POWERFUL · image end 0x2DF38

What makes it powerful

The strength is not the skill count. It is how the mechanisms connect, compound, and stay reviewable.

  1. Committed knowledge has a system of record Architecture, commands, deployment facts, and dated pitfalls live in named reference files, not one chat transcript.
  2. Recall is routed and evidence-backed /recall selects the relevant topic, reads the actual file, cites its lines, and saves new lessons in the right home.
  3. Correction changes the harness itself /refine maps one observed friction to the smallest reviewable rule, memory, or workflow edit, so each fix can stand or roll back alone.
  4. New repositories begin from facts /init-project detects the stack first, asks only for unresolved decisions, seeds references, and prunes irrelevant capability.
  5. One playbook source serves both runtimes Claude workflows remain canonical. Generated Codex adapters add discovery, safety guidance, and honest capability gates without duplicating bodies.
  6. Improvements propagate selectively /sync-starter moves generic fixes across repositories while protecting project-specific rules and memory from bulk replacement.
  7. Hard work can require independent evidence Long-horizon, impartial review, and visual audit loops use fresh contexts only when the runtime proves those tools exist.
